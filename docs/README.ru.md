# MERIDIAN ELECTRONICS

Локальная версия пет-проекта: Angular 22 + TypeScript + SCSS, JavaScript / Express 5, SQLite. Сохранены товары, цены и изображения исходного архива. Каталог содержит демонстрационные данные.

## Запуск

Установите Node.js 24.15 или новее в ветке 24 LTS. Откройте терминал в папке проекта:

```powershell
npm.cmd ci
npm.cmd run build
npm.cmd start
```

Откройте http://localhost:3000. Создайте аккаунт через «Войти → Регистрация». База `data/meridian.sqlite` создаётся автоматически. Готовых пользователей и паролей в поставке нет.

Для разработки: `npm.cmd run dev`. Интерфейс доступен на http://localhost:4200, API — на http://127.0.0.1:3000. Изменения интерфейса обновляются автоматически. В Windows используйте `npm.cmd`, если PowerShell запрещает запуск `npm.ps1`.

## Реализовано

- Адаптивная главная, каталог, поиск, категории, сортировка цен и фильтр наличия.
- Карточки товаров с характеристиками и остатками.
- Регистрация, вход, выход, сохранение сессии, смена пароля с отзывом остальных сессий.
- Избранное и корзина с сохранением в аккаунте. Для использования нужен вход.
- Количество, удаление товаров, оформление заказа с телефоном и адресом.
- Серверный расчёт суммы, проверка и уменьшение остатков в одной транзакции.
- Кабинет с историей и составом заказов, профилем и настройками безопасности.
- Заявки на сборку компьютера с бюджетом и пожеланиями, список заявок в кабинете.
- Проверка форм, ошибки и пустые состояния, блокировка повторных нажатий.

Оплата — при получении. Доставка в учебной версии бесплатная. Реальных списаний денег нет.

## Структура и разработка

- `src/app/` — Angular standalone-компоненты, страницы, состояние на signals, API-клиент.
- `src/styles.scss` — SCSS-переменные, стили и адаптивные правила.
- `server/app.js` — HTTP API, проверка данных и доступа.
- `server/db.js` — схема SQLite и начальные товары.
- `server/index.js` — сервер и раздача собранного интерфейса.
- `tests/` — интеграционная проверка API.
- `public/img/` — изображения из исходного проекта.

Команды: `npm.cmd test`, `npm.cmd run build`, `npm.cmd run format`, `npm.cmd run format:check`. Зависимости зафиксированы в package-lock.json.

Тест использует отдельную базу в памяти: проверяет изоляцию пользователей, регистрацию, уникальность email, cookie, защиту Origin, количество и остатки, подмену суммы, откат заказа, профиль, заявки, смену пароля, отзыв сессий и выход. Рабочие данные не затрагиваются. Браузерная проверка регистрации, избранного, корзины и оформления выполнена на отдельной тестовой базе, не входящей в поставку.

## Хранение и размещение

Пароли хешируются scrypt с индивидуальной солью. Сессии действуют 7 дней; в БД хранится хеш токена, cookie имеет HttpOnly и SameSite=Lax. Production включает Secure. SQL использует параметры, запросы изменения требуют специального заголовка и проверки Origin. Есть Helmet, ограничения частоты запросов и размера JSON.

Переменные окружения:

| Переменная | По умолчанию          | Назначение                        |
| ---------- | --------------------- | --------------------------------- |
| PORT       | 3000                  | Порт сервера                      |
| DB_PATH    | data/meridian.sqlite  | Файл базы                         |
| APP_ORIGIN | http://localhost:3000 | Разрешённый адрес интерфейса      |
| NODE_ENV   | не задана             | production включает Secure-cookie |

Сервер слушает 127.0.0.1. Для размещения нужен HTTPS reverse proxy, APP_ORIGIN с реальным HTTPS-адресом, NODE_ENV=production и постоянный диск для базы. Настройки доверенного proxy и лимитов IP нужно согласовать с выбранным хостингом. Для резервной копии остановите сервер и сохраните папку data. Не добавляйте базу в Git. SQLite рассчитана на один серверный процесс; для масштабирования потребуются PostgreSQL и общее хранилище лимитов. Последующие изменения схемы требуют миграций (сейчас user_version=1).

## Что ещё нужно для коммерческого запуска

Не подключены платёжный провайдер, почтовая верификация и восстановление пароля, операторские уведомления, админ-панель товаров/остатков/статусов и реальные тарифы доставки. Заказы остаются в статусе «Новый», заявки — «Сохранена». Нет изменения email и отмены заказов пользователем. Для публикации также нужны реальные условия доставки и возврата, политика обработки данных, мониторинг и резервное копирование.

Исходный архив не изменён. Старые PHP-файлы не используются: авторизация содержала SQL-интерполяцию, а часть кнопок была заглушками.

Документация: [Angular](https://angular.dev/reference/versions), [Node.js SQLite](https://nodejs.org/api/sqlite.html).

## Сохранение исходного дизайна

Восстановлены исходные логотип и иконки, заголовок главной, блоки преимуществ и «О магазине», восемь популярных товаров, контакты и чёрный подвал. `src/original.scss` адаптирует исходный визуальный стиль к Angular-компонентам. В каталоге возвращены боковые фильтры, баннер и рабочая пагинация без дублирования товаров. Старые HTML-адреса перенаправляются на соответствующие страницы приложения.

В кабинете доступны профиль, избранное, заказы, сборки, поддержка, подарки, реквизиты, личная информация и безопасность. Поддержка использует контакты из оригинала. Подарочная программа и привязка платёжных карт не подключены: разделы показывают честные пустые состояния. Баннер MacBook сохранён с отметкой об отсутствии товара. Фильтры технических параметров содержат только известные характеристики; неизвестные диагонали не выдумываются.
